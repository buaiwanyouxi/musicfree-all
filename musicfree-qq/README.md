# QQ音乐音源插件（qq.js）使用说明

> **平台**：QQ音乐（腾讯系）｜ **版本**：v0.1.4 ｜ **作者**：tianpeng
> **适配**：[MusicFree](https://github.com/maotoumao/MusicFree) 桌面端 / 移动端

---

## 一、插件定位

将「QQ音乐」作为一个独立音源接入 MusicFree，实现搜索、歌词、排行榜、热门歌单、歌单导入等完整能力。

**接口契约**：

- **浏览类（搜索 / 歌词 / 排行榜 / 热门歌单 / 歌单导入）**：走**旧版 cgi-bin 免签端点**（如 `c.y.qq.com` 的 `s.pl` / `v8/fcg` 等），无需签名；
- **播放取链**：`CgiGetVkey` 本身免签，但其返回的 `purl` 需要登录态 `authst` Cookie 才能拼接出可播直链。

> 注意：`musicu.fcg` 已全面加签名，本插件浏览类已避开该端点，统一走免签旧版接口。

### 取链四层兜底（核心能力）

QQ 官方取链依赖登录态——**未登录时原曲基本全挂**。为此实现四层兜底，保证尽量有歌可播：

1. **① 官方 QQ（CgiGetVkey）**：需登录 Cookie 解锁，返回腾讯官方 CDN 直链（最高音质）；
2. **② 首选备用 AAX音乐网（aax.cx）**：条目自带时长，可做**歌名 + 作者 + 时长**三重校验（最严，抗同名异长错曲），自动过人机验证并缓存 50 分钟；
3. **③ 次选备用 无名音乐网（mvmp3.com）**：按 `【歌手 - 歌名】` 做歌名 + 作者双重校验，自动完成「我不是人机」验证并后台预热；
4. **④ 末选备用 无忧音乐网（qeecc.com）**：与 aax 同源 CMS，详情页为 `/song/<id>.html`，作为最后一层兜底。

> 四层**并发启动**，采纳顺序 ② → ③ → ④，整段 9s 软上限；未登录时自动走备用源，实测 `晴天` / `去年夏天` 等 1.7—2.1s 可取到可播直链。
>
> **说明**：② ③ ④ 三站均为聚合站，最终多落「酷我系 CDN」（`s.5bb3.com` / `car-*.kuwo.cn`），实测 `302 → 206 audio/*` 可正常播放。三站曲库覆盖不同，故采用并发竞速 + 逐级降级，而非单源依赖。

### 歌词三级兜底（v0.1.4 新增）

**问题**：早期版本取链有四层兜底，歌词却只有 QQ 官方一条路——凡是"靠备用源才播得出来"的曲（跨源歌单/收藏导入、外源 ID、无 songmid），歌词必然空白。

**现改为三级链**：

1. **① QQ 官方歌词**：先做 songmid 形态校验（14 位 base62，避免拿外源 ID 盲试），返回后必须通过有效性校验；无版权曲的 `retcode=-1901` 空歌词**不再被当作成功**；
2. **② 取链时顺带缓存的该源歌词**：播放取链成功时顺手写入缓存（**零额外请求**），且天然与**实际播放的音源**同源同轴。mvmp3 的取链接口直接内联歌词；aax 的歌词是 URL，由后台异步预取；
3. **③ 按「歌名 + 歌手」在 mvmp3 / aax 并发反查**：**8s** 软上限，复用身份校验防张冠李戴；两站取首个有效结果。

> **质量控制**：任何一级的歌词都必须通过有效性校验（含时间轴的真实歌词行 ≥ 8 字符），并过滤站点**占位歌词**（如 aax 的「暂无歌词内容」）与**水印行**（如 mvmp3 的「无名音乐网 www.mvmp3.com」）。
>
> **为什么不用 qeecc 的歌词**：实测其歌词端点 `/js/lrc.php` 对任意入参恒返回 `{"code":200,"msg":"LRC歌词加载成功","lrc":""}` —— **假成功**，永远拿不到内容，故排除出歌词链。
>
> **代价**：播放后打开歌词面板为**缓存命中（0 额外请求）**；若先开歌词面板再播放，冷路径需 **2.4—3.6s**（三个备用源的会话均在**插件加载后 4s**与**每次搜索**时后台预热、40 分钟续期；未预热时实测 6.7—7.1s）。

### 备用源会话预热（v0.1.4 扩展至三源）

三个备用源（mvmp3 / aax / qeecc）同为「酷我系 CMS」，人机验证握手约需 2—4s。若等到真正使用时才握手，这笔开销会压在**首次取链**或**首次歌词反查**上。

故在**插件加载后 4 秒**、**每次搜索**、以及**每 40 分钟**（会话有效期约 50 分钟）后台预热三源会话，使用时直接命中热缓存：

| 场景 | 未预热 | 预热后 |
|---|---|---|
| 歌词反查（单源） | 6.7—7.1s | **2.4—3.6s** |
| 歌词反查（整段，两站并发取首个） | — | **2.6—2.7s** |
| 搜索本身 | — | 636ms（预热异步，不阻塞搜索） |

## 二、支持功能

| 功能 | 方法 | 说明 |
|------|------|------|
| 搜索 | `search` | 仅单曲（music） |
| 播放取链 | `getMediaSource` | 四层兜底（见上） |
| 单曲信息 | `getMusicInfo` | 时长/歌手/专辑/封面 |
| 歌词 | `getLyric` | 三级兜底（官方 → 播放源缓存 → mvmp3/aax 反查），见上 |
| 排行榜 | `getTopLists` / `getTopListDetail` | 按分类分组（飙升/新歌/特色/全球等） |
| 热门歌单 | `getRecommendSheetTags` / `getRecommendSheetsByTag` | 6 个分类分组 + 置顶「全部」 |
| 歌单导入 | `importMusicSheet` | 粘贴 QQ 音乐歌单链接/ID |
| 歌单详情 | `getMusicSheetInfo` | 点进歌单后的歌曲列表 |

### 歌单导入格式

- QQ音乐 APP：歌单 → 分享 → 复制链接，粘贴即可导入；
- 网页：复制歌单 URL（含 `/playlist/数字` 或 `disstid=数字`）粘贴，或直接输入纯数字歌单 ID；
- 导入时间与歌单大小有关，请耐心等待。

## 三、所需配置（可选）

| 配置项 key | 名称 | 必填 | 说明 |
|------------|------|------|------|
| `cookie` | Cookie（可选） | 否 | QQ 音乐登录后的会话 Cookie。填入后用于解锁「① 官方 QQ 取链」（需含 `authst` / `uin`）。搜索、歌词、排行榜、热门歌单、歌单导入通常**无需** Cookie。**未填也能播**——自动走 aax / mvmp3 / qeecc 备用音源。 |
| `mvmp3_cookie` | mvmp3 Cookie（可选） | 否 | 无名音乐网(mvmp3)的人机验证由插件自动完成，无需手动操作；会话约 50 分钟自动刷新。若自动过验证偶发失败，可在此填 mvmp3 的 `PHPSESSID`（站点 `https://www.mvmp3.com` 登录 / F12 取 Cookie）以跳过自动验证。**AAX音乐网(aax.cx) 与 无忧音乐网(qeecc.com) 的人机验证同样由插件自动完成，无需任何配置。** |

## 四、安装方法

MusicFree →「设置」→「插件设置」→「从网络安装插件」→ 填入下方**订阅地址**；或「从文件安装」选择本地 `qq.js`。

**主地址（jsdelivr · 固定标签 · 全球加速）**

```
https://cdn.jsdelivr.net/gh/buaiwanyouxi/musicfreemusicfree-all@v0.1.4/musicfree-qq/qq.js
```

**备选地址（Gitee · 国内直连）**

```
https://gitee.com/koujiao/musicfree-tianpeng/raw/master/musicfree-qq/qq.js
```

> **为什么用「固定标签」而不是分支地址**：`@v0.1.4` 是 jsdelivr 的**静态版本**，内容不可变并被永久缓存，新版发布后**立即分发**；而分支地址（`@main`）有最长 **12 小时**的 CDN 缓存，新版本可能迟迟不到位。同时该地址与插件内部 `srcUrl` 字段**完全一致**，插件「更新」时回访的仍是同一份文件，**不会出现版本回退**。
>
> ⚠️ 每次发版须同步：① 修改 `qq.js` 内 `version` 与 `srcUrl`（指向新标签）；② 推送文件；③ 在 GitHub 对应提交上打同名标签。三者缺一，更新链即会出现「标签不存在」或「版本回退」。

## 五、已知限制与修复记录

1. **热门歌单崩溃（已修复）**：早期 `getRecommendSheetTags` 返回扁平数组，导致歌单广场 `group.data.forEach` 崩溃；已修复为 **6 个分类分组数组 + 置顶「全部」**，`getRecommendSheetsByTag` 兼容空 `tag.id` 落「全部」并加 try/catch。
2. **未登录取链**：未填 Cookie 时官方层全部失败，但 ② / ③ / ④ 备用层保证可播；若四层均失败会抛出明确错误提示（含各层失败原因）。
3. **移动端闪退（已修复）**：`artwork` 返回空串会触发原生图片组件崩溃；现统一为「真实封面 URL 或 `undefined`」，绝不返回空串。
4. **v0.1.3 换源**：删除 Tonzhon 网易云匹配源（其 weapi 链路长、失败率高，且需内置整套 AES-128-CBC 实现），改为 aax.cx + qeecc.com 两个与 mvmp3 同源 CMS 的聚合站。该段核心逻辑由 10004 字符降至 9409 字符，并新增「aax 时长三重校验」与「3xx 重定向信任」两项修复（文件整体 +1.6KB，主要来自新增的中文协议注释）。
5. **aax 直链 302 说明**：aax 返回的 `s.5bb3.com/*.m4a` 会 `302` 跳转到酷我 `car-*.kuwo.cn` CDN，故 `validatePlayable` 对未跟随到底的 `3xx` 一律信任放行，避免把可播链误杀成「播放失败」。
6. **v0.1.4 歌词兜底（修复「备用源播放时无歌词」）**：根因是取链有四层兜底、歌词只有官方一条路，且官方返回 `retcode=-1901` 空歌词时静默返回空串。实测复现：跨源曲（外源 ID / 无 songmid）能播但歌词为空，**2/3 用例复现**；修复后同用例全部取到歌词（1075—1613 字符）。同时修复「非 QQ songmid 盲试官方取链白等约 5s」——跨源曲取链 **6893ms → 2207ms**。歌词缓存复用实测 **2660ms → 0ms**。
7. **v0.1.4 srcUrl 自引用链修复**：原 `srcUrl` 指向**首次**提交，而该提交内部的 `srcUrl` 又指向更早的 v0.1.2 提交，形成「每回访跳一跳、版本逐代后退」的引用链——用户在 MusicFree 内点「更新 / 重装」会退回 **v0.1.2**，歌词修复随之丢失。现改为指向 jsdelivr **固定标签 `@v0.1.4`**：文件内容与引用指针完全自洽，且标签属静态版本、永久缓存不可 purge，不受 CDN 缓存窗口影响。同步修正 `module.exports` 中 `version` / `author` 两行的缩进错位。
